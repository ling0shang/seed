C++有一个库，叫做Boost，家喻户晓。

> Boost 官方按类别组织库，核心分类包括：**算法、并发编程、容器、数据结构、错误处理、函数对象、泛型编程、I/O、数学、内存、解析、字符串与文本处理、系统、模板元编程**等。它被称为“准标准库”，因为 `shared_ptr`、`regex`、`filesystem`、`thread` 等大量组件后来进入了 C++ 标准。



作为一个C++学习者，向着手搓对标Boost库的目标看齐，设计开发一个库，应该对提升我自己有很大的帮助。就像播下的种子萌发成长一样，这就是Seed的由来。



当然，个人精力是有限的，况且现如今古法编程少见，流行vibe coding，所以我只学习开发了一些对找工作、理解四大件、计算基本功、软件设计及架构等方面有帮助的模块。



下面是我问`deepseek`以及搜集资料之后，整理的一些愿景：



## 前置调查



### 聚焦求职

综合牛客、小红书和培训机构的信息，C++ 校招简历上被反复提及、且面试官确实会追问的手搓方向高度集中于：

| 方向                  | 对应 Boost 类别      | 求职价值                                                     | 能力覆盖                     |
| :-------------------- | :------------------- | :----------------------------------------------------------- | :--------------------------- |
| **内存池 / 分配器**   | 内存                 | 高频，面试常问“为什么不用 malloc”                            | 内存布局、系统调用、性能分析 |
| **线程池 / 并发组件** | 并发编程             | 几乎必问，连接池/无锁队列常被提及                            | 多线程、同步原语、任务调度   |
| **协程库**            | 并发编程（间接相关） | **差异化强**，比烂大街的 webserver 有优势                    | 上下文切换、状态机、I/O 模型 |
| **网络库 / Reactor**  | I/O（Asio 的领域）   | 后端岗位核心，但工程量大，建议做“精简 Reactor”而非完整网络库 | 网络编程、epoll、事件驱动    |
| **配置 / 序列化**     | I/O、解析            | 中等，适合作为**第一个完整垂直切片**                         | 解析、API 设计、错误处理     |







### 给 seed 空项目的具体起步路径

**第一步：先做“前置基础模块”，而不是直接冲热门轮子。** 你现在的 seed 是空项目，缺的是可复用的底座。优先手搓下面这些，它们会被后续所有模块依赖：

- **`seed::expected` / `Result`**：错误处理策略，决定整个项目的 API 风格。
- **字符串/文件基础工具**：trim、split、文件读取、路径处理。这些是 INI 和后续配置模块的直接依赖。
- **测试骨架 + CI**：选 doctest 或 Catch2，把测试跑通。没有测试的轮子项目在简历上很脆弱。

**第二步：做一个“小而完整”的垂直切片。** 推荐顺序是：**INI（配置 backend）→ 内存池 → 线程池 → 协程/Reactor**。INI 放第一个，因为它的复杂度可控，能让你快速获得“一个模块从设计到文档全部走完”的体感。但**不要把它当成核心卖点**，在简历上它可以作为“基础组件”的一部分，而不是主打项目。

> 因为当时的对话上下文是有哪些ini解析库，怎么开发一个类似的？

**第三步：热门轮子要追求“理解深度”而非“代码量”。** 牛客上有一条很务实的评论：“轮子项目关键要质量高”。内存池不到 1000 行就足够完整，协程库的核心价值在于你能讲清楚**有栈/无栈、对称/非对称、和线程进程的区别**。面试官不会因为你写了 5000 行网络库就高看你，但会因为你讲清楚了“为什么用内存池而不是 malloc”而认可你。



### 一个需要避开的坑

不要同时铺开多个轮子。你现在的知识储备是“半年 C++ + 学习者”，最稀缺的不是想法，而是**把一个模块做透、做完整、能讲清楚的精力**。seed 项目的第一个里程碑应该是：**一个能在 CI 上跑通测试、有 README 和设计文档、API 经过至少一次反思重构的小模块**。哪怕它只是 INI，也比五个烂尾的热门轮子更有说服力。

总结一句：**把 Boost 当成一张分类地图，而不是一座要爬的山。** 从地图上圈出“内存、并发、I/O”三个与求职最相关的区域，用 seed 项目作为练习场，一个模块一个模块地手搓、测试、文档化、复盘。INI 可以作为第一个，但你的主线始终应该是**内存池和并发组件**。

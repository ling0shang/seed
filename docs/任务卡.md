### M0

```

│   ├── version.hpp

├── src/

├── tests/
│   ├── CMakeLists.txt
│   ├── test_version.cpp
│   └── test_string.cpp
├── examples/
├── docs/design/
│   ├── 0001-project-charter.md
│   └── 0002-module-admission.md
└── .github/workflows/ci.yml
```



#### T0.2 写 README 和两份设计文档

`README.md` 必须包含：项目定位、非目标、构建方式、测试方式、路线图、模块准入标准链接。
`0001-project-charter.md`：把我们上面的章程写进去。
`0002-module-admission.md`：写入六条准入标准。



#### T0.3 最小 CMake 可构建

要求：

- C++17；
- 先做**小编译库** `seed`，不要一开始全 header-only；
- 开启警告：GCC/Clang `-Wall -Wextra -Wpedantic -Werror`，MSVC `/W4 /WX`；
- `include/seed/version.hpp` + `src/version.cpp` 提供 `seed::version()`。



#### T0.4 引入 doctest 并跑通 ctest

用 FetchContent 或 vendored 方式引入 doctest。
测试 `version()` 返回非空。
验收命令：



```bash
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```



#### T0.5 实现 `seed::trim` 并写边界测试

API 建议：



```cpp
namespace seed {
std::string trim(std::string_view sv);
}
```



测试必须覆盖：空串、全空白、前后空白、`\t\r\n`、无空白、中间空白保留。
这是你第一个“真实小函数”，要按正式模块标准做。



#### T0.6 配 GitHub Actions CI

先做 Ubuntu + Windows 矩阵，macOS 可选。
步骤：checkout → 配置 CMake → 构建 → ctest。
验收：CI 绿。



#### T0.7 第一次复盘

写 `docs/design/0003-m0-retro.md`：做了什么、遇到什么问题、CMake/链接/CI 学到什么、下一阶段风险。





#### M0 验收标准

只有同时满足下面全部条件，M0 才算完成：

1. `cmake -S . -B build && cmake --build build && ctest --test-dir build --output-on-failure` 本地通过；
2. GitHub Actions Ubuntu + Windows 绿；
3. `version` 和 `trim` 有测试，`trim` 边界用例齐全；
4. README、章程、准入标准、M0 复盘四份文档存在；
5. 提交历史是小步提交，不是一次性大提交；
6. 你能口头讲清楚：为什么选 C++17、为什么用 doctest、CMake 目标是什么、CI 在验证什么。

**M0 期间禁止开发API功能，**比如ini， 这是范围纪律。
